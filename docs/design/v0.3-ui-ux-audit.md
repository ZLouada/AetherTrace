# AetherTrace v0.3 UI/UX Audit
**Wireshark for AI Agents — Design System, Interaction Architecture, and Developer Ergonomics**

---

## 1. Executive Summary

AetherTrace is the local-first visual debugger, live interceptor, and time-travel replay engine for AI agents ("Wireshark for AI Agents"). Through v0.1.0 and v0.2.0 (Phases 0 through 16), AetherTrace has established an industry-leading technical core: deterministic agent graph parsing, time-travel replay, sub-agent grouping, tool-chain intelligence, causal DAG analysis, Needleman-Wunsch diffing, multi-generation forks, and local zero-eval guardrails.

However, the user interface and developer ergonomics currently reflect an **organic accretion of features across 16 rapid engineering phases**. While functionally complete and stable, the interface exhibits structural UX debt:
1. **Visual Identity Divergence**: The design token foundation lacks AetherTrace's primary brand accent (AetherTrace Orange), falling back on generic dark-mode blues, purples, and indigos.
2. **Viewport & Density Constraints**: Rigid fixed-width sidebars (280px) and inspector drawers (460px) consume more than 50% of standard 1080p/laptop displays, suffocating the DAG canvas and Timeline waterfall.
3. **Modal Trapping & CSS Hacks**: Heavy workstation environments—specifically the Replay & Experiment Studio and the Evaluation Studio—are confined within dialog modals using negative margin breakout hacks (`-m-6 h-[750px]`) that clip on sub-900px vertical viewports.
4. **Canvas Scalability Clutter**: Span nodes in the DAG canvas default to large 320px cards rendering multi-line payload previews, causing visual chaos and prohibitive navigation overhead on traces with 50+ spans.
5. **Keyboard & Workflow Disconnect**: While powerful keyboard shortcuts exist, they lack on-screen discoverability, unified focus trapping, and seamless single-keystroke resolution for live intercepted breakpoints.

The goal of **AetherTrace v0.3.0** is not to rebuild the application, redesign backend APIs, or mimic another product's brand. Rather, it is to apply **disciplined developer-first product principles**—high density, information hierarchy, monospace precision, subdued borders, keyboard-first navigation, and zero decorative fluff—elevating AetherTrace into a premier developer workstation.

---

## 2. Current Design Strengths

Despite UX friction points, the existing v0.2.0 interface contains several outstanding foundational strengths that must be preserved:

1. **High Technical Density & Monospace Rigor**:
   - Spans prominently display prompt tokens, completion tokens, execution latency, exact USD micro-costs, cache status, and execution origins (`original`, `modified`, `mocked`, `new_execution`).
   - Technical metadata (UUIDs, timestamps, hashes) is presented with monospace formatting and one-click copy targets.
2. **Deterministic Information Grounding**:
   - Zero "fake AI" decorative visuals, zero conversational chatbots, and zero nebulous status spinners. Every visualization maps 1:1 to deterministic telemetry emitted by the SQLite database and proxy logs.
3. **Sub-Agent & Tool-Chain Intelligence Grouping**:
   - The Phase 11 agent grouping engine correctly aggregates sub-agent spans into collapsible parent nodes (`AgentGroupNode.tsx`), drastically reducing DAG edge complexity.
   - Intelligent badges for retries, guardrail blocks, tool chains, and critical path bottlenecks are already computed deterministically.
4. **Deep Interception & Debugging Architecture**:
   - The UI supports real-time paused states, manual breakpoint evaluation, chaos fault injection (rate limits, timeouts, status codes), and multi-variant prompt forks directly from the frontend.
5. **Integrated Full-Text Search (FTS5) & Command Palette**:
   - The `CommandPalette.tsx` component interfaces directly with backend SQLite FTS5 indexes for fast query parsing (`status:error`, `event:tool`, `cost:>0.10`).

## 3. Current UX Problems

### Problem 3.1: Canvas Claustrophobia from Rigid Dual-Panel Layout
- **Problem**: The central DAG canvas and bottom timeline are severely constrained by non-resizable side panels.
- **Evidence**: `RunSidebar.tsx` has a hardcoded width of `w-[280px]` (collapsible only to `w-12`), and `InspectorDrawer.tsx` has a fixed width of `w-[460px]`. On a standard 1366×768 or 1440×900 display, 740px of horizontal real estate is consumed by static chrome, leaving under 50% for graph inspection.
- **Why it matters**: Developers spend their time panning and zooming the canvas repeatedly rather than reading execution flows. Complex parallel agent traces appear crowded and truncated.
- **Recommended solution**: Replace fixed-width containers with a flexible, drag-resizable split pane layout. Support double-click to collapse, minimum and maximum width clamps, and viewport-aware responsive auto-docking.
- **Priority**: P0

### Problem 3.2: Studio Workstations Trapped Inside Dialog Modals
- **Problem**: Full-scale analytical suites (Experiment Studio, Evaluation Studio, Diff Arena) are mounted as popup modals over the Flight Deck canvas instead of full workstation views.
- **Evidence**: `ExperimentStudio.tsx` forces `-m-6 h-[750px]` and `EvaluationPanel.tsx` forces `-m-6 h-[700px]` inside `Modal.tsx`.
- **Why it matters**: Running multi-variant replays, configuring mutation matrices, and evaluating assertion tables requires expansive screen space. In a modal, content scrolls inside sub-containers, creating multiple scrollbars and clipping critical action buttons on laptop viewports.
- **Recommended solution**: Transition Studios from popup modals to dedicated first-class workstation view modes or full-canvas tabs (`/debug`, `/diff`, `/experiments`, `/eval`) with seamless keyboard tab switching (`⌘1` through `⌘4`).
- **Priority**: P0

### Problem 3.3: Excessive Cognitive Load in TopBar Navigation
- **Problem**: The top navigation bar is cluttered with ten heterogeneous action buttons lacking semantic grouping.
- **Evidence**: `TopBar.tsx` displays Live pill, Run selector, Search, Breakpoints, Chaos, Diff Arena, Experiment Studio, Evaluation Studio, Export, and Shortcuts side-by-side in a single cramped flex row.
- **Why it matters**: Operators cannot visually distinguish between live session controls, analytical tools, and workspace toggles. Visual hierarchy is lost.
- **Recommended solution**: Consolidate the top bar into three distinct zones:
  1. *Left*: Workspace / Active Run context & live connection indicator.
  2. *Center*: Primary View Switcher tabs (`Trace DAG`, `Timeline`, `Diff Arena`, `Experiment Studio`, `Evaluation Studio`).
  3. *Right*: Quick Debug Actions (`Pause/Resume`, `Breakpoints`, `Chaos`), Command Palette trigger (`⌘K`), and Settings.
- **Priority**: P1

## 4. Design-System Problems

### Problem 4.1: Absence of Primary Brand Accent Token in Design System
- **Problem**: The core design tokens and Tailwind theme omit AetherTrace Orange, relying on generic blues, purples, and indigos.
- **Evidence**: In `apps/flight-deck/src/design-system/tokens.ts`, `categoryTokens` maps `LLM` to blue, `AGENT` to teal, and `HTTP` to purple. `tailwind.config.ts` extends zinc shades but defines zero accent palette or brand orange.
- **Why it matters**: AetherTrace's defined identity is "black / white / grey foundation with AetherTrace orange as primary accent". Without token-level definition, developers introduce ad-hoc colors, producing inconsistent focus rings, active states, and brand dissonance.
- **Recommended solution**: Introduce `accent` tokens into `tokens.ts` and `tailwind.config.ts`:
  - `accent.DEFAULT`: `#ea580c` (Orange 600)
  - `accent.hover`: `#f97316` (Orange 500)
  - `accent.subtle`: `rgba(234, 88, 12, 0.12)`
  - `accent.border`: `rgba(249, 115, 22, 0.35)`
- **Priority**: P0

### Problem 4.2: Invalid Tailwind Micro-Padding Class `py-0.2`
- **Problem**: Multiple core design components use the non-existent Tailwind utility class `py-0.2`.
- **Evidence**:
  - `apps/flight-deck/src/design-system/Badge.tsx`: lines 35, 41, 47, 53, 58
  - `apps/flight-deck/src/components/nodes/SpanNode.tsx`: lines 161, 206
  - `apps/flight-deck/src/components/CommandPalette.tsx`: lines 696, 697, 698, 699
- **Why it matters**: `py-0.2` is ignored by the Tailwind compiler because Tailwind only recognizes valid numeric steps (e.g. `py-0.5`) or arbitrary values with brackets (e.g. `py-[1px]`). Consequently, badges and shortcut keys render with `padding-top: 0; padding-bottom: 0`, clipping text baselines and causing vertical misalignment.
- **Recommended solution**: Standardize micro-padding across the design system using `py-0.5` (2px) or `py-[1px]` for ultra-dense technical badges.
- **Priority**: P1

### Problem 4.3: Violation of Clean-Tech Aesthetic Guardrails (Glassmorphic Blur)
- **Problem**: Backdrop blur filters are applied to modal overlays and command palette dialogs.
- **Evidence**: `Modal.tsx` line 52 (`backdrop-blur-[2px]`), `CommandPalette.tsx` line 564 (`backdrop-blur-[2px]`).
- **Why it matters**: Directly violates the design directive: *"no glassmorphism, no fake AI visuals, no purple/blue SaaS gradients"*. In addition, `backdrop-filter` creates composite layer thrashing on Linux X11/Wayland and low-end GPUs, causing stutter when opening the command palette.
- **Recommended solution**: Eliminate `backdrop-blur-[2px]`. Use solid, crisp, high-contrast dark scrims: `bg-black/75` or `bg-[#000000]/80` with a sharp 1px border on dialog containers (`border-[#2c2c32]`).
- **Priority**: P1

### Problem 4.4: Monospace Overuse & Missing Sans UI Typography Stack
- **Problem**: Monospace font is indiscriminately applied to all UI chrome, including button labels, tab headers, and modal text.
- **Evidence**: `globals.css` sets `font-family: var(--font-jetbrains-mono)` on `body`. `SpanNode.tsx` sets `font-mono` on the container, but resets `font-sans` on the body paragraph.
- **Why it matters**: Universal monospace degrades reading comprehension for natural language prompts, labels, and interface commands. Monospace is essential for code, hashes, token counts, and timestamps, but interface controls should utilize a crisp, geometric sans-serif stack (e.g. Inter or system UI sans) for superior optical rhythm.
- **Recommended solution**: Establish a two-tier typography contract:
  - `font-sans` (`Inter`, system-ui): TopBar, navigation, tabs, button labels, modal headers, documentation.
  - `font-mono` (`JetBrains Mono`, `Fira Code`): Span IDs, hashes, timestamps, token numbers, JSON payloads, metrics, code snippets.
- **Priority**: P2

### Problem 4.5: Hardcoded Hex Literals Bypassing Design Tokens
- **Problem**: UI components are littered with raw hex literals (`#18181c`, `#111114`, `#202024`, `#2c2c32`, `#09090b`) directly in JSX className strings instead of semantic design tokens.
- **Evidence**: `DataRow.tsx` line 34, `Tooltip.tsx` line 39, `Divider.tsx` lines 15 & 17, `InspectorDrawer.tsx` line 382, `SpanNode.tsx` lines 124 & 148.
- **Why it matters**: Makes global theme calibration, contrast adjustments, and border-subtlety refinement impossible without editing dozens of individual files.
- **Recommended solution**: Map all surface colors to semantic Tailwind theme tokens (`bg-surface-canvas`, `bg-surface-panel`, `bg-surface-card`, `bg-surface-hover`, `border-subtle`, `border-focus`).
- **Priority**: P2

## 5. Navigation Problems

### Problem 5.1: Missing Multi-View Workspace Navigation Architecture
- **Problem**: AetherTrace v0.2.0 is conceptually split between live debugging (Flight Deck) and analytical tools (Diff, Experiments, Evaluation), but navigation forces everything into overlay modals over a single background page.
- **Evidence**: `apps/flight-deck/src/app/page.tsx` maintains boolean state flags `[showDiffModal, setShowDiffModal]`, `[showExperimentStudio, setShowExperimentStudio]`, and `[showEvaluationPanel, setShowEvaluationPanel]`.
- **Why it matters**: Developers cannot bookmark, URL-route, or keep multiple analytical contexts open side-by-side. Closing a modal loses in-progress experiment draft state.
- **Recommended solution**: Implement a unified top-level workspace switcher:
  - `[1] Traces & DAG` (Live Interceptor / Debugger)
  - `[2] Diff Arena` (Run vs Run comparison)
  - `[3] Experiment Studio` (Variants, Mutations, Matrix Replay)
  - `[4] Evaluation Studio` (Deterministic Assertions, Root Cause Analysis)
- **Priority**: P0

### Problem 5.2: Run Switching Navigation Inefficiency
- **Problem**: Switching between runs requires opening the 280px sidebar, scrolling through bulky cards, and clicking, or opening the Command Palette and typing run IDs.
- **Evidence**: `RunSidebar.tsx` has no keyboard shortcut for next/previous run (e.g. `Option + ↑/↓`).
- **Why it matters**: When iterating through 10 quick test runs, the developer is forced to context-switch to the mouse to click tiny list items.
- **Recommended solution**: Add global shortcuts `[` and `]` or `Option + j/k` to cycle to previous/next execution runs immediately, updating the canvas without opening drawers.
- **Priority**: P2

## 6. Flight Deck Problems

### Problem 6.1: Run Sidebar Visual Over-Carding and Low Density
- **Problem**: Each trace run in `RunSidebar.tsx` is wrapped in an individual card with thick borders, multiple badges, and redundant labels.
- **Evidence**: `RunSidebar.tsx` lines 120–185 renders each run with `p-3 rounded border`, 3 distinct flex rows, and multiple badge tags.
- **Why it matters**: Only 4 to 5 runs fit on screen before vertical scrolling is required. High-velocity agent testing generates dozens of runs that should be scannable at a glance.
- **Recommended solution**: Implement a high-density tabular list view (Linear-style issue list):
  - Row height: 32px
  - Column 1: Status dot (green/red/amber/ping)
  - Column 2: Run Name / ID snippet
  - Column 3: Span count (`24 spans`)
  - Column 4: Cost (`$0.012`)
  - Column 5: Duration (`2.4s`)
  - Column 6: Relative timestamp (`2m ago`)
- **Priority**: P1

### Problem 6.2: Action Bar Disconnect Between Live and Replayed Runs
- **Problem**: Controls for live interception (Pause, Breakpoints, Chaos) remain prominently enabled even when inspecting an immutable historical run or imported trace.
- **Evidence**: `TopBar.tsx` renders `Pause` / `Resume` and `Breakpoints` regardless of whether the selected run is `running` or `completed`.
- **Why it matters**: Confuses the developer into believing they can pause or intercept an execution that finished minutes ago.
- **Recommended solution**: Contextualize the TopBar action strip. If the active run is historical, show Replay/Fork/Diff action buttons; if the active run is live/connected, show Intercept/Pause/Chaos actions.
- **Priority**: P2

## 7. DAG Problems

### Problem 7.1: Span Node Large Footprint Destroys Graph Navigation at Scale
- **Problem**: Span nodes default to 320px wide cards containing full prompt previews, token counters, and badges.
- **Evidence**: `SpanNode.tsx` line 124 sets `w-[320px]`. In a graph of 80 spans across 4 sub-agents, the DAG spans over 4,000 pixels horizontally and 3,000 pixels vertically.
- **Why it matters**: Developers must constantly zoom out to understand overall architecture, at which point the 320px card text is unreadable, or zoom in and lose all contextual orientation.
- **Recommended solution**: Implement a **Dual-Density View Mode**:
  1. *Compact Node Mode (Default for >20 spans)*: A 180px × 44px slim bar displaying Agent Icon, Model Badge, Status Indicator, and Latency/Cost pill.
  2. *Detailed Node Mode*: The existing 320px rich card, activated on hover, node selection, or when toggled via a density switch (`D` shortcut).
- **Priority**: P0

### Problem 7.2: Dagre Layout Jitter & Layout Shift on Collapse
- **Problem**: Collapsing or expanding an agent group causes Dagre to recalculate coordinates from scratch, causing an abrupt layout jump that resets developer viewport focus.
- **Evidence**: `DagCanvas.tsx` runs `getLayoutedElements` on every change to `collapsedAgents` or `filterTerm`.
- **Why it matters**: Disorients the operator and interrupts root-cause tracing during live debugging sessions.
- **Recommended solution**: Use smooth coordinate interpolation (CSS transition or React Flow node transition) or anchor the selected node during graph relayout.
- **Priority**: P1

### Problem 7.3: Inconsistent Selection Highlights Between Single and Multi-Select
- **Problem**: When multiple nodes are selected via `M` (multi-select mode), nodes turn indigo, whereas single selection is zinc/white, and critical path nodes turn amber.
- **Evidence**: `SpanNode.tsx` lines 131–138 evaluates `isIntercepted`, `isBreaker`, `isSelected`, `isMultiSelected`, `isCriticalPath` with competing border and ring colors.
- **Why it matters**: Visual clutter: a node that is both on the critical path, held by a breakpoint, and multi-selected displays conflicting border and shadow rules.
- **Recommended solution**: Establish a strict priority order for node borders:
  1. Held Breakpoint (Flashing Amber border + ring)
  2. Guardrail Block / Error (Red border)
  3. User Selection (AetherTrace Orange 2px ring)
  4. Critical Path (Subtle amber underglow / badge)
  5. Multi-Selected (Orange dotted outline)
- **Priority**: P2

## 8. Inspector Problems

### Problem 8.1: Information Fragmentation Across Four Deep Tabs
- **Problem**: The Inspector drawer segregates essential span debugging data across four tabs: Overview, Intelligence, Fork IDE, and JSON.
- **Evidence**: `InspectorDrawer.tsx` lines 427–482. To check whether an error was caused by an upstream agent retry, the user must click "Intelligence", scroll down to "Causal Chain", then click back to "Overview" to see the prompt payload.
- **Why it matters**: Excessive clicking and context switching slows down root cause analysis.
- **Recommended solution**: Redesign the Inspector into a unified, high-density split view:
  - *Header*: Sticky metadata summary (Span ID, Model, Agent, Status, Latency, Cost, Token pill, Action buttons).
  - *Main Body*: Collapsible sections with keyboard shortcuts (`1` for Payload, `2` for Intelligence, `3` for JSON).
  - *Footer*: Action bar with direct Replay, Fork, and Pin commands.
- **Priority**: P1

### Problem 8.2: Fork IDE Raw JSON Editor Usability Deficits
- **Problem**: The Fork IDE provides a bare JSON textarea for modifying prompt messages, lacking syntax validation, schema hints, or side-by-side comparison with the original prompt.
- **Evidence**: `InspectorDrawer.tsx` lines 188–201 parses `request_payload` into a raw textarea string `forkMessagesJson`.
- **Why it matters**: Easy to produce malformed JSON syntax errors when editing prompts. Developers cannot see what they changed compared to the original run.
- **Recommended solution**: Provide a structured prompt editor with:
  - Role pills (`system`, `user`, `assistant`, `tool`).
  - Formatted text boxes for prompt messages.
  - Quick "Compare with Original" diff toggle.
  - `⌘ + Enter` to execute fork immediately.
- **Priority**: P2

## 9. Timeline Problems

### Problem 9.1: Fixed Bottom Dock Lacks Flexible Zoom & Granular Scrubbing
- **Problem**: The timeline drawer is docked to the bottom with fixed height (`h-64`, 256px), and its horizontal scaling is locked to total trace duration.
- **Evidence**: `apps/flight-deck/src/components/Timeline.tsx` calculates span bar percentage strictly based on `(span.start_time - minTime) / totalDuration`.
- **Why it matters**: In a trace lasting 60 seconds with 20 parallel tool calls executing in 50ms, those 50ms spans collapse into hairline 1-pixel slivers that cannot be clicked or inspected.
- **Recommended solution**: Add timeline scrub-zoom functionality (mouse wheel / trackpad pinch to zoom into sub-second ranges), a time-ruler header marked in milliseconds, and min-width clamping (minimum 6px clickable width for micro-spans).
- **Priority**: P1

### Problem 9.2: Missing Synchronized Cursor Between Timeline and DAG
- **Problem**: Hovering over a span bar in the Timeline does not highlight the corresponding node in the DAG canvas, and hovering over a DAG node does not indicate its position on the Timeline.
- **Evidence**: `Timeline.tsx` manages independent hover state `hoveredSpanId` without notifying `DagCanvas.tsx`.
- **Why it matters**: Developers cannot easily correlate temporal concurrency in the waterfall with topological dependency in the graph.
- **Recommended solution**: Lift `hoveredSpanId` to shared Flight Deck context; highlight the matching DAG node with a pulsing focus indicator when hovered in the timeline, and vice-versa.
- **Priority**: P2

## 10. Replay / Debugging Problems

### Problem 10.1: Live Breakpoint Interception Lacks Immediate Visual Urgency & Keyboard Actions
- **Problem**: When a breakpoint is triggered by an agent, the span enters the `intercepted` state, but the operator must notice the amber node border, click the node, scroll down inside the Inspector, and click "Resume" or "Mock".
- **Evidence**: `InspectorDrawer.tsx` lines 487–560 renders breakpoint controls inside the drawer body.
- **Why it matters**: Defeats the primary promise of "Wireshark for AI Agents": rapid, keyboard-driven packet/call interception. In a live agent loop, the developer wants immediate notification and instant single-key resolution.
- **Recommended solution**: Display a high-visibility **Floating Intercept HUD** at the top center of the canvas whenever spans are held:
  ```text
  [⏸️ 1 CALL INTERCEPTED] Agent: Planner • gpt-4o • "tools/execute_sql"
  [R] Resume | [M] Mock Response | [E] Edit Payload | [A] Abort
  ```
  Allow instant resolution with single keystrokes (`R`, `M`, `A`) without touching the mouse.
- **Priority**: P1

### Problem 10.2: Chaos Engineering Fault Injection Discovery
- **Problem**: The Chaos modal allows injecting simulated rate limits (429), server errors (500), and latency delays, but there is no visual indicator on the canvas showing which rules are currently armed.
- **Evidence**: `ChaosModal.tsx` stores active chaos configuration, but the Flight Deck canvas has no persistent banner indicating that chaos simulation is active.
- **Why it matters**: A developer might forget that a 429 rate-limit rule is armed, run an agent, observe failures, and mistakenly conclude that their model provider is down.
- **Recommended solution**: When chaos rules are active, render a persistent, compact amber indicator in the TopBar: `⚡ Chaos Active (2 rules)` with a one-click "Disarm All" action.
- **Priority**: P2

## 11. Diff Arena Problems

### Problem 11.1: Diff Arena Cluttered Modal Presentation
- **Problem**: The Diff Arena is forced into a modal dialog with multiple nested sub-panels, making side-by-side run comparisons cramped and unreadable.
- **Evidence**: `apps/flight-deck/src/components/DiffArenaModal.tsx` mounts inside `Modal.tsx` with `maxWidth="6xl"`.

- **Recommended solution**: Upgrade Diff Arena from a modal dialog to a full-screen dedicated workstation view mode (`/diff` or Tab 2), utilizing the entire display width with synchronized split scrolling.

- **Problem**: In the Diff Arena span comparison, text differences between prompt versions or tool outputs are displayed as entire raw strings rather than character/word-level diff highlights.
- **Evidence**: `DiffArenaModal.tsx` renders payload strings in standard monospace pre blocks without inline diff decorations.
- **Why it matters**: When an agent prompt is modified by only a few words (e.g. changing instructions or system messages), the developer cannot spot what changed without reading both blocks side-by-side.
- **Recommended solution**: Integrate inline character-level or token-level diff highlighting (green additions, red deletions) using clean, non-intrusive syntax coloring.
- **Priority**: P2

## 12. Experiment / Evaluation Problems

### Problem 12.1: CSS Negative-Margin Hacks and Viewport Clipping in Studio Modals
- **Problem**: `ExperimentStudio.tsx` and `EvaluationPanel.tsx` use negative margins (`-m-6`) and fixed heights (`h-[750px]`, `h-[700px]`) to counteract the parent modal's default padding.
- **Evidence**:
  - `apps/flight-deck/src/components/ExperimentStudio.tsx`: line 235 (`-m-6 h-[750px] flex flex-col`)
  - `apps/flight-deck/src/components/EvaluationPanel.tsx`: line 273 (`-m-6 h-[700px] flex flex-col`)
- **Why it matters**: Negative margin hacks cause layout clipping on smaller screens (height < 900px), hide bottom action buttons, and break accessibility focus outlines. This is an explicit anti-pattern.
- **Recommended solution**: Remove the studio modals entirely. Convert Experiment Studio and Evaluation Studio into full-screen view modes with responsive CSS flexbox layout (`h-full w-full`) without arbitrary fixed pixel heights.
- **Priority**: P0

### Problem 12.2: Evaluation Studio Assertion Table Density
- **Problem**: Evaluation assertions are displayed as wide, tall cards rather than compact tabular rows.
- **Evidence**: `EvaluationPanel.tsx` renders each assertion result in a card with stacked status, name, target, and message rows.
- **Why it matters**: Evaluating 20 assertions requires continuous scrolling. A test summary scorecard should provide an immediate, scannable overview of pass/fail metrics.
- **Recommended solution**: Adopt a clean tabular view: Status Icon (Check/X), Assertion ID, Type, Expected, Actual, and Delta, with expandable failure details.
- **Priority**: P2

## 13. Keyboard UX

### Problem 13.1: Modal Focus Trapping Deficiencies & Esc Duplication
- **Problem**: Modals and drawers set `aria-modal="true"`, but do not trap focus. Pressing `Tab` cycles focus through hidden elements on the background canvas. In addition, `Escape` key handling is duplicated across `page.tsx`, `Modal.tsx`, and `CommandPalette.tsx`.
- **Evidence**: `Modal.tsx` lines 34–42 registers a `keydown` listener for Escape, while `page.tsx` line 185 registers an independent Escape listener.
- **Why it matters**: Pressing Escape can close multiple nested layers simultaneously (e.g. closing both an input tooltip and the entire experiment modal), causing loss of work.
- **Recommended solution**: Implement a centralized `KeyboardManager` or `useFocusTrap` hook with an explicit modal stack. Only the topmost modal receives the Escape event and traps Tab navigation.
- **Priority**: P1

### Problem 13.2: Missing Keyboard Shortcuts for Core Studio Workflows
- **Problem**: High-frequency actions in Experiment Studio and Diff Arena (e.g. "Run All Variants", "Export Matrix", "Toggle Failed Only") have no keyboard shortcuts.
- **Evidence**: No keydown listeners exist in `ExperimentStudio.tsx` or `EvaluationPanel.tsx`.
- **Why it matters**: Power developers must continuously switch back and forth between keyboard and mouse during rapid evaluation cycles.
- **Recommended solution**: Wire standard keyboard shortcuts:
  - `⌘ + Enter`: Execute Active Experiment / Run Evaluation
  - `Option + F`: Toggle "Show Failures Only"
  - `⌘ + S`: Save Experiment Preset / Assertion Suite
- **Priority**: P2

## 14. Accessibility

### Problem 14.1: Contrast Failures on Micro-Text Elements
- **Problem**: Numerous micro-text labels use `text-[10px]` with `text-zinc-500` (#71717a) on dark background surfaces (#111114).
- **Evidence**: Contrast ratio between `#71717a` and `#111114` is 3.19:1, failing WCAG 2.1 AA requirement of 4.5:1 for small text. Found in `SpanNode.tsx` (line 183), `TopBar.tsx` (line 92), `RunSidebar.tsx` (line 145), and `CommandPalette.tsx` (line 677).
- **Why it matters**: Unreadable for users with moderate visual impairment, or when working in bright environments or on low-contrast laptop displays.
- **Recommended solution**: Elevate secondary technical metadata from `text-zinc-500` to `text-zinc-400` (#a1a1aa, 5.8:1 contrast ratio) and increase minimum text size for critical metadata to `11px`.
- **Priority**: P1

### Problem 14.2: Missing Semantic ARIA Roles on Canvas Nodes & Timeline
- **Problem**: React Flow canvas nodes and timeline bars are rendered using plain `div` tags without ARIA roles, states, or screen-reader accessible labels.
- **Evidence**: `SpanNode.tsx` container (line 124) is an untyped `div` with no `role="article"` or `aria-label`.
- **Why it matters**: Screen readers cannot announce span execution order, status changes, or parent-child hierarchy to visually impaired engineers.
- **Recommended solution**: Add appropriate ARIA attributes: `role="treeitem"`, `aria-selected={isSelected}`, and descriptive `aria-label="Agent [name] - [status] - [model] - latency [ms]ms"`.
- **Priority**: P2

## 15. Responsive UX

### Problem 15.1: Layout Collapse on 1366×768 and Standard 14-inch Laptop Screens
- **Problem**: The Flight Deck UI is designed implicitly for large desktop displays (1920×1080 and above). On standard 1366×768 or 1440×900 screens, the combination of sidebar (280px), canvas, inspector (460px), and timeline (256px) leaves almost zero working area.
- **Evidence**: Fixed pixel widths on sidebar and inspector with no CSS media queries or responsive breakpoints in `page.tsx`.
- **Why it matters**: Developers frequently debug agents on laptops while traveling or away from multi-monitor setups. The tool becomes unusable on compact screens.
- **Recommended solution**: Implement responsive breakpoint behavior:
  - `< 1280px`: Auto-collapse sidebar to compact icon strip (48px); dock Inspector into an overlay sheet or bottom tab.
  - `< 1024px`: Stack views into full-screen switchable panels.
- **Priority**: P1

## 16. Performance / Rendering UX

### Problem 16.1: Dagre Graph Layout Recalculation Overhead
- **Problem**: Filtering by search term or toggling agent group collapse triggers an immediate full Dagre graph recomputation in the browser main thread.
- **Evidence**: In `DagCanvas.tsx`, `getLayoutedElements` executes synchronously on every state update.
- **Why it matters**: In traces with 500+ spans, calculating node layout takes 80–150ms on the main thread, causing frame drops and input lag when typing into the filter box.
- **Recommended solution**: Memoize Dagre layout calculations; debounce search filter changes by 150ms; run heavy graph calculations in a Web Worker or cache node layout positions by agent group.
- **Priority**: P1

## 22. Regression Risks

During v0.3 UI/UX refinement, the following specific regression risks must be actively guarded against:

1. **React Flow / Dagre Coordinate Desynchronization**:
   - *Risk*: Introducing compact span nodes or resizable panels could distort Dagre's node dimensions, resulting in disconnected edges or misaligned handles.
   - *Mitigation*: Ensure compact and detailed node dimensions are explicitly registered in Dagre calculation constants (`NODE_WIDTH`, `NODE_HEIGHT`).
2. **Replay & Mutation Lineage State Loss**:
   - *Risk*: Transitioning Experiment Studio from a modal to a full view could cause state loss if component unmounting clears active variant drafts.
   - *Mitigation*: Persist active experiment configuration in a dedicated Zustand or React Context store rather than local component state.
3. **Keyboard Shortcut Conflicts with Input Elements**:
   - *Risk*: Global hotkeys (e.g. `p` for pin, `m` for multi-select, `r` for resume) could trigger while the user is typing inside search inputs or JSON textareas.
   - *Mitigation*: Always check `event.target` tag name (`INPUT`, `TEXTAREA`) before triggering global navigation shortcuts.
4. **Canvas Pan & Zoom Resets**:
   - *Risk*: Switching between View Switcher tabs could reset canvas zoom level and pan coordinates, frustrating the developer.
   - *Mitigation*: Preserve React Flow viewport state (`{ x, y, zoom }`) across tab switches.
